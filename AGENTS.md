# Q-HUB Operating Rules

Read docs/MASTER_GOAL.md in full before implementation. It is the authoritative specification; this file is a durable working summary, not a replacement.

## Source integrity

- Q-HUB and its canonical repository are the only implementation source of truth.
- This is a greenfield product. Do not preserve or imitate any previous Quantum implementation, route, code, copy, media, metadata, or design decision.
- Never open, crawl, search, quote, or use www.quantum-hub.com, cached/archived versions of it, AmirNatan1/Quantum-Site, AmirNatan1/Final-Q-Hub, or previous Codex Quantum implementations.
- Do not import old Quantum images or use stock industrial imagery. Do not generate fake Quantum facilities or POC photography.
- Missing information stays missing. Never invent corporate facts, partner relationships, metrics, measurements, quotes, POC outcomes, or commercial results.

## Truth and publication

- Keep business/content truth, creative truth, and implementation truth separate.
- Corporate facts may come only from the master goal, publication-approved structured content/media supplied to Q-HUB, or explicit user instruction.
- Every substantive record carries classification A, B, C, or D and publicApproved.
- Public production may render only A + approved or B + approved. It must never render B + unapproved, C, or D.
- Development placeholders must be machine-identifiable and unmistakably non-factual.
- sourceReferenceInternal must never be emitted in public output.
- Keep content, publication eligibility, and presentation as separate layers. Validate content with typed schemas and automated tests.

## Product and creative contract

- Quantum Hub is an industry and technology platform. The central proposition is: QUANTUM TURNS INDUSTRIAL NEEDS INTO FIELD EVIDENCE.
- The internal principle is THE FIELD IS THE INTERFACE.
- The experience sequence is FIND → TEST → PROVE.
- The material transformation is ABSTRACTION → FIELD → EVIDENCE.
- Phase 1 is one continuous SIGNAL → APERTURE → NEED → FIND → TEST → PROVE journey, not six interchangeable sections.
- FIND uses distributed possibility and controlled search; TEST introduces material contact, friction, and constraint; PROVE settles into structured evidence.
- Use selective, meaningful realtime graphics only. Never add generic particles, chrome objects, cyber grids, decorative 3D, or canvas-only information.
- Generic corporate templates, startup-card grids, fake dashboards, glassmorphism, stock factories, and generic AI aesthetics are unacceptable.

## Engineering contract

- Static-first Astro and strict TypeScript target GitHub → Cloudflare Pages.
- Essential copy, navigation, and state meaning render as semantic HTML before enhancement.
- Phase 1 uses a small, lazy custom WebGL enhancement with an authored DOM/CSS fallback. Do not add React, Three.js/R3F, GSAP, or another heavy runtime without a documented need and measured benefit.
- Keep heavy code outside the initial critical path. Reserve layout space, load responsive media deliberately, use adaptive quality, stop inactive rendering, and survive enhancement failure.
- Expose all six experience states through stable data attributes suitable for Playwright.
- Vitest covers schemas/publication logic; Playwright covers behavior, modes, viewports, accessibility, console errors, and visual evidence.

## Inclusion and input

- Mobile is authored, not a shrunken desktop. Translate pointer exploration into touch/scroll-native progression.
- Reduced motion is a designed resolved experience, not blanket animation removal.
- Maintain semantic landmarks, valid headings, keyboard operation, visible focus, accessible names, WCAG AA contrast, forced-colors resilience, 44px touch-target intent, and no hover-only content.
- Every meaningful canvas state has equivalent DOM content. Navigation and essential content never wait for WebGL.

## Completion discipline

- Measure build health and performance; never fabricate evidence or scores.
- Treat H1–H15 as hard gates. Record commands, evidence, limitations, and defects truthfully.
- Stop after Phase 1 and the Human Review Package. Human review alone decides ACCEPT, REPAIR, or REDIRECT; do not proceed into Phase 2 automatically.
