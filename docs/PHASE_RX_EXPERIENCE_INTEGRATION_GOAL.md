## Purpose

Phase R-X preserves the accepted Phase R strategy, visual identity, publication boundary, seven-act homepage, Proof system, and sparse-copy approach while repairing real-use integration defects. The target experience must feel spatially deliberate, immediately responsive to ordinary wheel/trackpad/touch input, and complete at every state boundary.

This is not a redesign and not another content phase. It is a bounded refinement of the existing homepage:

`PRESENCE → ACCESS → STARTUP → METHOD → ACTIVITY → EVIDENCE → ACTION`

## Human problem statement

The pre-repair homepage had three linked defects:

1. Several desktop compositions felt cramped or insufficiently integrated with their viewport.
2. Signature transformations behaved like discrete CSS scenes that caught up after input rather than staying coupled to scroll progress.
3. Long sticky runways and threshold-switched visuals made ordinary wheel input feel as though it had to be repeated before the page responded.

The repair must distinguish and test scroll architecture, semantic state thresholds, sticky geometry, time-based transitions, and actual runtime performance. A passing performance score cannot substitute for continuous visual response.

## Native-scroll contract

Normal mode must expose `html[data-scroll-choreography="continuous"]`. Each homepage section must expose continuously updated local progress while active. ACCESS, STARTUP, METHOD, and ACTIVITY must derive their visible geometry directly from that progress on the same animation-frame update as native scrolling.

Semantic data states remain stable review/test landmarks, but they must not be the sole visual driver. Time-based CSS transitions must not continue catching up after scroll input ends. Forward and reverse scroll must update immediately and reversibly.

The implementation must not:

- call `preventDefault()` for wheel/touch scrolling;
- synthesize or replace browser momentum;
- use a smooth-scroll library;
- enable scroll snap;
- require an unlock gesture;
- hide essential state inside canvas;
- trap the user in a sticky scene.

CSS `scroll-behavior` for conventional anchor navigation is not a runtime scroll engine and must not alter wheel behavior.

## Spatial repair contract

### ACCESS

Preserve the borderless, full-viewport Partner Field and exact partner sequence. Desktop identities must receive clear resolved intervals and handoffs without stacking as cards. Mobile must remain a normal-flow sequence of five large identity territories.

### STARTUP

Preserve the Field Crossing proposition and round → compressed → rectilinear morphology. Copy owns a protected reading region. On narrow screens the transformation lane moves below the copy/action instead of crossing readable text.

### METHOD

Preserve FIND → TEST → PROVE words and material meaning. Geometry must continuously interpolate through search distribution, contact/constraint, and registered evidence, including reverse scroll. No completion UI is permitted.

### ACTIVITY

Preserve the four exact approved activity labels and distinct spatial conditions. Desktop transitions continuously through each condition. Mobile and reduced motion expose a readable, non-overlapping normal-flow list rather than a compressed sticky runway.

### EVIDENCE and ACTION

Preserve the accepted calm document field and decisive engagement ending. Their handoff must release naturally from the activity scene and avoid excess vertical runway.

## Accessibility and fallback contract

- Reduced motion removes continuous choreography and resolves a complete normal document flow.
- Touch/mobile does not initialize WebGL by default and uses authored layout rather than pointer emulation.
- No WebGL preserves all state hooks, copy, actions, and CSS geometry.
- No JavaScript preserves the semantic reading order and all essential content.
- Forced colors preserves names, labels, actions, and visible focus while removing non-essential decoration.
